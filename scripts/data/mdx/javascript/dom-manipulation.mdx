<Summary>
  The Document Object Model (DOM) is a programming interface for web documents.
  It represents the page so that programs can change the document structure,
  style, and content. The DOM represents the document as nodes and objects; that
  way, programming languages can connect to the page.
</Summary>

<InfoBlock>
  <InfoBlockHeader title="Selecting Elements" tag="QUERY_SELECTOR" />
  <InfoBlockText>
    Before you can manipulate elements, you must first access them within the
    document tree. Modern JavaScript provides powerful methods to target nodes
    by ID, class, or tag name.
  </InfoBlockText>

  <InfoBlockListContainer>
    <InfoBlockListItem>
      <InfoBlockInlineCode>document.getElementById()</InfoBlockInlineCode> -
      Fast, specific selection by unique ID.
    </InfoBlockListItem>

    <InfoBlockListItem>
      <InfoBlockInlineCode>document.querySelector()</InfoBlockInlineCode> -
      Versatile, uses CSS selector syntax.
    </InfoBlockListItem>

    <InfoBlockListItem>
      <InfoBlockInlineCode>document.querySelectorAll()</InfoBlockInlineCode> -
      Returns a NodeList of all matches.
    </InfoBlockListItem>

  </InfoBlockListContainer>
  ```js
  const hero = document.querySelector('.hero-title');
```
</InfoBlock>

<LearnSection title="Mental Model">
  Think of generics like blanks in a template. When you use the function or
  class, TypeScript fills in those blanks with actual types. This means your
  code can adjust to whatever data type it’s given—like a function that works
  the same for strings, numbers, or custom objects.
</LearnSection>

<LearnSection title="When to Use">
  <ul>
    <li>When you need a function or class to handle many types safely.</li>
    <li>
      For data structures like arrays, maps, or caches that store various types.
    </li>
    <li>
      When building reusable libraries, utilities, or hooks (like in React).
    </li>
    <li>To preserve type relationships between inputs and outputs.</li>
  </ul>
</LearnSection>

<LearnSection title="Pitfalls">
  <ul>
    <li>
      Avoid using <code>any</code>; it removes type safety.
    </li>
    <li>
      Overly complex or unnecessary generics can make code harder to read.
    </li>
    <li>
      Type inference can fail—sometimes you’ll need to specify the type
      manually.
    </li>
    <li>
      JSX can misinterpret <code>&lt;T&gt;</code> as a tag...
    </li>
  </ul>
</LearnSection>
